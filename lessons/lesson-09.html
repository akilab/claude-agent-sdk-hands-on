Lesson 09 / Agent SDK

構造化出力とログを保存する

Lesson 09では、Agentの最終結果を自由な文章ではなく、Pythonで扱いやすい辞書として受け取ります。 `output_format` と JSON Schemaで出力の形を指定し、`ResultMessage.structured_output` と実行ログをファイルに保存します。

所要時間 60分
ゴール 実行前の確認 初出APIの見方 output_formatの読み方 シーケンス図 処理の流れ 構造化出力を書く 実行して確認 確認問題

Goal

このレッスンのゴール

このレッスンを一言で JSON Schemaを渡し、構造化された最終結果を `ResultMessage.structured_output` から受け取ります。

  • 自由形式の文章と構造化出力の違いを説明できる
  • JSON Schemaで、Agentに返してほしいデータの形を定義できる
  • `ClaudeAgentOptions(output_format=...)` の役割を説明できる
  • `ResultMessage.structured_output` が `ResultMessage` の属性であると理解できる
  • 構造化出力と実行ログを別々のJSONファイルに保存できる

Before run

実行前の確認

Lesson 09は、Lesson 08までと同じ `python-labs/` のuv環境で動かします。 まず `claude_agent_sdk` が読み込める状態か確認してください。

Windows / macOS / Linux 
uv run python -c "import claude_agent_sdk; print('claude_agent_sdk OK')"
この回ではツールを使わせません

構造化出力そのものに集中するため、`Read`、`Glob`、`Edit`、`Write`、`Bash` は禁止します。 Agentには、スクリプト内にある会議メモを読み取り、指定したJSON Schemaに合う形で返してもらいます。

SDK concepts

初めて出てくる関数・クラス・属性

このレッスンでは、SDKの新しい設定として `output_format` を使います。 あわせて、Python標準ライブラリの `json` と `datetime` も、実行結果を保存するために使います。

名前 分類 インスタンス生成 Lesson 09での使い方
output_format `ClaudeAgentOptions` に渡す引数 不要。辞書を渡す Agentの最終結果をJSON Schemaに合う構造化データとして返すよう指定する。
ResultMessage.structured_output `ResultMessage` の属性 不要。SDKから返る `ResultMessage` が持つ 検証済みの構造化出力を取り出す。`subtype` の中にあるのではなく、`ResultMessage` 自体の属性。

Schema detail

`output_format` と JSON Schema を読む

公式ドキュメントでは、Pythonの場合 `output_format` に `{"type": "json_schema", "schema": ...}` の形を渡します。 これにより、Agentの完了時に `ResultMessage` の `structured_output` 属性へ検証済みデータが入ります。

今回作りたいのは、会議メモから「要約」「決定事項」「担当チームごとのTODO」「リスク」を取り出したJSONです。 先に完成形を見ておくと、`OUTPUT_SCHEMA` はその形をAgentに守らせるための設計図だと読みやすくなります。

作りたいJSONの形 
{
  "summary": "会議メモ全体の短い要約",
  "decisions": [
    "決定事項を文字列で並べる"
  ],
  "todos": [
    {
      "team": "担当チーム名",
      "task": "そのチームが行う作業",
      "priority": "high / medium / low のどれか"
    }
  ],
  "risks": [
    "注意すべき点や未確定事項を文字列で並べる"
  ]
}
Lesson 09で使うoutput_format 
output_format={
    "type": "json_schema",
    "schema": OUTPUT_SCHEMA,
}
キー 意味 今回の例
type 値の種類を指定する。object、array、string、numberなどを使う。 全体は object。TODO一覧は array。
properties objectが持つ項目名と、それぞれの型を定義する。 summary、decisions、todos、risks。
required 必ず含める項目を指定する。 4つのトップレベル項目と、TODO内の team、task、priority。
enum 許可する値を限定する。 priority を high、medium、low に限定。
description 項目の意図を説明する。検証条件ではなく、Agentへの手がかりとして使う。 要約、決定事項、TODO、リスクの意味を説明。
スキーマは最初から複雑にしすぎない

構造化出力は、スキーマに合うJSONを生成できないと失敗することがあります。 公式ドキュメントでは、失敗時の `subtype` として `error_max_structured_output_retries` が示されています。 まず小さく確実なスキーマから始め、必要に応じて項目を増やします。

Sequence

構造化出力が保存される順番を図で見る

`structured_output` は `subtype` の中にある値ではありません。 `ResultMessage` が持つ別の属性として返ってくるため、完了状態を見る処理と、構造化データを取り出す処理を分けて読みます。

Before coding

コードを書く前に処理の流れを読む

Lesson 09のコードは、Agentの出力を「人が読む結果」と「プログラムが後で使うデータ」に分けて保存します。 関数の関係は次の順番で追うと理解しやすくなります。

  1. `main()` が `asyncio.run(run_agent())` で非同期処理を起動する
  2. `run_agent()` が `build_options()` と `build_prompt()` を呼ぶ
  3. `build_options()` が `output_format` にJSON Schemaを設定する
  4. `query(prompt=..., options=...)` がAgentを実行し、メッセージを順に返す
  5. `AssistantMessage` なら途中応答を表示する
  6. `ResultMessage` なら `message.structured_output` を直接読み、構造化出力を取り出す
  7. `build_run_log()` が完了状態、ターン数、時間、コストなどのメタ情報をまとめる
  8. `save_outputs()` が構造化出力と実行ログを `outputs/` に保存する

Hands-on

構造化出力とログ保存を書く

`python-labs/practice/lesson_09_structured_output_log.py` を作り、次のコードを入力してください。 長めですが、JSON Schema、Agent実行、ResultMessage処理、ファイル保存の関係を一つの流れとして読むため、省略せずに書きます。

python-labs/practice/lesson_09_structured_output_log.py 
import asyncio
import json

from claude_agent_sdk import (
    AssistantMessage,
    ClaudeAgentOptions,
    ResultMessage,
    query,
)

from shared.display import print_section
from shared.files import write_json_file
from shared.logs import build_run_log
from shared.messages import print_assistant_message
from shared.paths import OUTPUT_DIR, PROJECT_ROOT


STRUCTURED_OUTPUT_PATH = OUTPUT_DIR / "lesson_09_structured_output.json"
RUN_LOG_PATH = OUTPUT_DIR / "lesson_09_run_log.json"


# このレッスンでは、下の会議メモをAgentに読ませます。
# Agentには自由な文章で感想を書かせるのではなく、
# 後でPythonから扱いやすいJSONに整理してもらいます。
MEETING_MEMO = """
社内FAQページの公開準備について打ち合わせを行った。
公開日は来月第2週を目標にする。
営業チームは、よくある質問を10件選ぶ。
法務チームは、公開前に表現を確認する。
開発チームは、検索しやすいページ構成を検討する。
サポートチームは、公開後の問い合わせ窓口を準備する。
未確定の仕様はFAQに断定表現で書かない。
""".strip()


# Agentに最終的に作ってほしいJSONのイメージです。
#
# {
#   "summary": "会議メモ全体の短い要約",
#   "decisions": [
#     "決定事項を文字列で並べる"
#   ],
#   "todos": [
#     {
#       "team": "担当チーム名",
#       "task": "そのチームが行う作業",
#       "priority": "high / medium / low のどれか"
#     }
#   ],
#   "risks": [
#     "注意すべき点や未確定事項を文字列で並べる"
#   ]
# }
#
# OUTPUT_SCHEMAは、このJSONの形をAgent SDKに伝えるための設計図です。
# Pythonの辞書として書いていますが、中身はJSON Schemaのルールです。
OUTPUT_SCHEMA = {
    "type": "object",
    "properties": {
        "summary": {
            "type": "string",
            "description": "会議メモ全体の短い要約",
        },
        "decisions": {
            "type": "array",
            "items": {"type": "string"},
            "description": "決定事項の一覧",
        },
        "todos": {
            "type": "array",
            "items": {
                "type": "object",
                "properties": {
                    "team": {"type": "string"},
                    "task": {"type": "string"},
                    "priority": {
                        "type": "string",
                        "enum": ["high", "medium", "low"],
                    },
                },
                "required": ["team", "task", "priority"],
            },
            "description": "担当チームごとのTODO",
        },
        "risks": {
            "type": "array",
            "items": {"type": "string"},
            "description": "注意すべきリスクや未確定事項",
        },
    },
    "required": ["summary", "decisions", "todos", "risks"],
}


# 構造化出力を得るためのOptionsを作る関数です。
def build_options() -> ClaudeAgentOptions:
    return ClaudeAgentOptions(
        cwd=str(PROJECT_ROOT),
        max_turns=2,
        # このレッスンはスキーマ指定に集中するため、ツールは使わせません。
        # 会議メモはPython文字列としてプロンプトに入れるので、Readも不要です。
        disallowed_tools=["Read", "Glob", "Edit", "Write", "Bash"],
        # output_formatは、Agentの最終回答の形を指定する設定です。
        # typeにjson_schemaを指定し、schemaに上で定義したOUTPUT_SCHEMAを渡します。
        output_format={
            "type": "json_schema",
            "schema": OUTPUT_SCHEMA,
        },
    )


# Agentに依頼するプロンプトを作る関数です。
def build_prompt() -> str:
    return f"""
次の会議メモを読み、JSON Schemaに合う形で構造化してください。
TODOのpriorityは high / medium / low のいずれかにしてください。

会議メモ:
{MEETING_MEMO}
""".strip()


# queryを呼び出し、構造化出力とログを保存する関数です。
async def run_agent() -> None:
    options = build_options()
    prompt = build_prompt()
    final_result = None
    structured_output = None

    print_section("Prompt")
    print(prompt)

    print_section("Agent output")
    async for message in query(
        prompt=prompt,
        options=options,
    ):
        if isinstance(message, AssistantMessage):
            print_assistant_message(message)
        elif isinstance(message, ResultMessage):
            final_result = message
            structured_output = message.structured_output

    if final_result is None:
        raise RuntimeError("ResultMessage was not received.")

    run_log = build_run_log(final_result, structured_output)

    if structured_output is not None:
        write_json_file(STRUCTURED_OUTPUT_PATH, structured_output)
    write_json_file(RUN_LOG_PATH, run_log)

    print_section("Structured output")
    if structured_output is None:
        print("No structured output was returned.")
    else:
        print(json.dumps(structured_output, ensure_ascii=False, indent=2))

    print_section("Saved files")
    print(STRUCTURED_OUTPUT_PATH)
    print(RUN_LOG_PATH)


# 非同期のrun_agent関数をイベントループで実行する関数です。
def main() -> None:
    asyncio.run(run_agent())


if __name__ == "__main__":
    main()

Review

確認問題

  1. 自由形式の文章ではなく、構造化出力を使うメリットを説明してください。
  2. `output_format={"type": "json_schema", "schema": OUTPUT_SCHEMA}` は何を指定していますか。
  3. `structured_output` は `subtype` の中にありますか。それとも `ResultMessage` の属性ですか。
  4. 構造化出力と実行ログを別ファイルに分ける理由を説明してください。
  5. `error_max_structured_output_retries` が出た場合、最初に何を見直しますか。

構造化出力を扱えると、Agentの結果を次の処理やUIへ渡しやすくなります。 次のLesson 10では、繰り返し使う判断や手順をSkillsとして設計する方向へ進みます。
