Lesson 19 / ClaudeSDKClient

JSON台帳をSQLiteへ登録する

Lesson 15で保存したJSON台帳を読み込み、Lesson 18で作ったSQLite DBへ登録します。 まずは会話一覧に必要な `users` と `sessions` だけを扱い、会話本文の `messages` は次の段階に分けます。

所要時間 55分
ゴール やること 実行前の確認 登録する範囲 ユーザー登録 処理の流れ 完成コードを読む 実行して確認 DB Browserで確認 確認問題

Goal

このレッスンのゴール

このレッスンを一言で JSON台帳の `users[].sessions[]` を、SQLiteの `users` と `sessions` に登録します。

  • JSON台帳からユーザーとセッションを取り出せる
  • `users` テーブルへユーザー記録を登録できる
  • `sessions` テーブルへClaude側の `session_id` を登録できる
  • DB Browserで登録結果を確認できる

What you will do

このレッスンでやろうとしていること

Lesson 15で作ったJSON台帳を、Lesson 18で作ったSQLite DBへ移します。 ここでは会話本文ではなく、まずユーザーとセッション一覧をDBへ登録することに集中します。

完成コードを動かし、JSONの `users[]` と `sessions[]` がDBの `users` と `sessions` に対応する様子を確認します。 `messages` はまだ空でよく、会話本文は次のレッスンで実際のClaude応答から保存します。

Before run

先に必要なファイル

このレッスンは、Lesson 15で作った `outputs/lesson_15_session_registry.json` を入力として使います。 まだ台帳がない場合は、先にLesson 15の完成版を実行して、少なくとも1つの `session_id` を保存してください。

Windows / macOS / Linux 
uv run python scripts/lesson_15_capture_session_id.py
Lesson 18のDB作成もコード側で呼びます

今回のコードは `create_schema()` を呼ぶため、DBやテーブルがまだない状態でも実行できます。 `create_schema()` の中身は `shared.database` に移しているため、このレッスンではJSON台帳をDBへ渡す流れに集中します。 ただし、学習の流れとしてはLesson 18でDB Browserから空のテーブルを確認しておくと、今回の変化が見えやすくなります。

shared.databaseは説明を短くするための共通部品です

`insert_user_if_missing()` や `insert_session_if_missing()` の中ではSQLを実行しています。 ただしLesson 19ではSQL文そのものではなく、JSON台帳の `user_record` と `session_record` をどの順番でDBへ渡すかを読みます。

古いDBを作っていた場合

以前の版で `users.created_at` や `users.updated_at` を含むDBを作っていた場合は、DB Browserを閉じてから `data/agent_sessions.sqlite3` を削除し、Lesson 18を実行し直してください。 SQLiteは既存テーブルの列を `CREATE TABLE IF NOT EXISTS` では自動的に減らしません。

Mapping

今回は本文をまだ入れない

JSON台帳には `transcript_path` も入っていますが、今回はファイル本文を読んで `messages` に入れるところまでは進みません。 まず、Web UIの会話一覧に必要になるユーザーとセッションだけをDB化します。 次のレッスンでは、新しい会話を実行しながら `messages` へ本文を保存します。

JSONの場所 登録先 今回扱うか
users[].user_id users.user_id 扱う
users[].sessions[].session_id sessions.claude_session_id 扱う
users[].sessions[].title sessions.title 扱う
users[].sessions[].transcript_path messages.content 次の段階で扱う

Insert user

ユーザーは「なければ追加」だけにする

`users` では、JSON台帳にある `user_id` をDBへ登録します。 学習用に割り切り、すでに同じ `user_id` がある場合は何もしません。 そのため、ユーザー登録は `INSERT OR IGNORE` だけで扱います。

UNIQUE制約がここで効きます

`users.user_id` と `sessions.claude_session_id` にはUNIQUE制約があります。 UUIDはほぼ被りませんが、DB側の制約で「同じIDを二重登録しない」ことも守ります。

sessionsも「なければ追加」に揃えます

このレッスンでは、セッションも `INSERT OR IGNORE` だけで登録します。 その細かいSQLは `shared.database` に置き、Lesson 19のコードでは `insert_session_if_missing()` を呼ぶだけにします。

Sequence

処理の流れを見る

`main()` はJSON台帳を読み込み、DBへ接続し、テーブルを用意してから、ユーザー、セッションの順に登録します。 親である `users` を先に入れてから、子である `sessions` を入れるのがポイントです。

Hands-on

完成コードを読む

`python-labs/scripts/lesson_19_import_registry_to_sqlite.py` の完成コードを確認します。 Agentは実行せず、すでに保存済みのJSON台帳をDBに移します。 DBへの細かいINSERT処理は `shared.database` に切り出してあるため、ここでは台帳を1人ずつ読み解く流れに集中します。

python-labs/scripts/lesson_19_import_registry_to_sqlite.py 
import json
from typing import Any

from shared.database import (
    connect_database,
    count_rows,
    create_schema,
    fetch_session_summary,
    insert_session_if_missing,
    insert_user_if_missing,
)
from shared.display import print_section
from shared.paths import OUTPUT_DIR


SESSION_REGISTRY_PATH = OUTPUT_DIR / "lesson_15_session_registry.json"


# Lesson 15で作ったJSON台帳を読み込む関数です。
def load_registry() -> dict[str, Any]:
    if not SESSION_REGISTRY_PATH.exists():
        raise FileNotFoundError(
            "Lesson 15の台帳が見つかりません。"
            "先に `uv run python scripts/lesson_15_capture_session_id.py` を実行してください。"
        )

    return json.loads(SESSION_REGISTRY_PATH.read_text(encoding="utf-8"))


# ユーザー記録のsessions配列を、安全にリストとして取り出す関数です。
def get_session_records(user_record: dict[str, Any]) -> list[dict[str, Any]]:
    sessions = user_record.get("sessions", [])
    if not isinstance(sessions, list):
        return []
    return sessions


# 1人分のユーザー記録を、usersとsessionsへ登録する関数です。
def import_user_record(
    connection,
    user_record: dict[str, Any],
) -> None:
    user_id = str(user_record["user_id"])
    insert_user_if_missing(connection, user_id)

    for session_record in get_session_records(user_record):
        insert_session_if_missing(connection, user_id, session_record)


# JSON台帳に入っている全ユーザーと全セッションをDBへ登録する関数です。
def import_registry_to_database(
    connection,
    registry: dict[str, Any],
) -> None:
    users = registry.get("users", [])

    for user_record in users:
        import_user_record(connection, user_record)

    connection.commit()


# 登録結果を、ターミナルで読みやすく表示する関数です。
def print_import_summary(connection) -> None:
    print_section("Imported row counts")
    print(f"users: {count_rows(connection, 'users')}")
    print(f"sessions: {count_rows(connection, 'sessions')}")
    print(f"messages: {count_rows(connection, 'messages')}")

    print_section("Session summary")
    for session in fetch_session_summary(connection):
        print(f"- {session['user_id']} / {session['claude_session_id']}")
        print(f"  title: {session['title']}")
        print(f"  updated_at: {session['updated_at']}")


# このファイルを直接実行したときの入口になる関数です。
def main() -> None:
    registry = load_registry()

    with connect_database() as connection:
        create_schema(connection)
        import_registry_to_database(connection, registry)
        print_import_summary(connection)


if __name__ == "__main__":
    main()

Run

実行して確認

`python-labs/` から実行します。

Windows / macOS / Linux 
uv run python scripts/lesson_19_import_registry_to_sqlite.py

正常に動くと、`Imported row counts` に `users`、`sessions`、`messages` の件数が表示されます。 今回は本文をまだ登録しないため、`messages` は `0` のままで正常です。

DB Browser

画面で登録結果を見る

DB Browser for SQLiteで `python-labs/data/agent_sessions.sqlite3` を開きます。 `Browse Data` タブで `users` と `sessions` を切り替えると、JSON台帳から移したデータを確認できます。

database is locked が出た場合

DB Browserで編集中のまま保存していると、Python側の書き込みが失敗することがあります。 その場合はDB Browser側で変更を保存または閉じてから、もう一度スクリプトを実行してください。

Review

確認問題

  1. 今回 `messages` に本文を入れなかった理由は何ですか。
  2. `users` を先に登録してから `sessions` を登録する理由は何ですか。
  3. `import_user_record()` は、1人分のユーザー記録に対して何をしていますか。
  4. `session_id` をDBでは `claude_session_id` として保存する理由をもう一度説明してください。
  5. DB Browserで `users` と `sessions` のどの列を確認すると、登録成功が分かりますか。
