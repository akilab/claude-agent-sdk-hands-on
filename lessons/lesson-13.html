Lesson 13 / ClaudeSDKClient

ClaudeSDKClient編で学ぶこと

ここからは `query()` の単発実行から一歩進み、`ClaudeSDKClient` で会話を続ける考え方を学びます。 FastAPIやWeb UIはまだ混ぜず、SDK単体で継続会話、セッション管理、複数ユーザー相当の分離、ストリーミングを整理します。

所要時間 35分
ゴール 実行前の確認 なぜClient編に進むか この章のロードマップ 初出APIの見方 セッションの考え方 確認コードを書く 確認問題

Goal

このレッスンのゴール

このレッスンを一言で `query()` から `ClaudeSDKClient` へ進む理由と、この章で学ぶ会話管理の全体像を整理します。

  • `query()` と `ClaudeSDKClient` の使い分けを説明できる
  • 継続会話、セッションID、resume、複数ユーザー相当の分離の関係を説明できる
  • ストリーミング表示を学ぶ前に、どのメッセージを読む必要があるか見通しを持てる
  • Web化の前にSDK単体で理解すべき項目を整理できる

Why client

なぜ `ClaudeSDKClient` 編に進むのか

Lesson 06〜12では、主に `query()` を使いました。 `query()` は、1つの依頼を送り、Agentから返るメッセージを最後まで読む用途に向いています。 一方で、チャットUIや複数回のやり取りでは、同じ会話の文脈を保ったまま次の質問を送りたくなります。

観点 query() ClaudeSDKClient
向いている用途 単発タスク。フォローアップしない処理。 同じプロセス内で続くマルチターン会話。
会話の継続 基本は新しい実行。必要なら `continue_conversation` や `resume` を使う。 同じclientに対する `client.query()` が、同じセッションを自動的に続ける。
接続の扱い 関数呼び出しの中でSDKが管理する。 `async with ClaudeSDKClient(...)` で開始と終了を明示する。
応答の読み方 async for message in query(...) await client.query(...) の後に client.receive_response() を読む。
中断 扱いにくい。 client.interrupt() を使える。
セッションの操作 Python SDK reference リアルタイムでレスポンスをストリーミングする

Section roadmap

この章で学ぶこと

ClaudeSDKClient編では、Webアプリに進む前の「会話管理の芯」を小さく学びます。 いきなりチャット画面を作らず、まずCLIで観察できる形にします。

順番 学ぶこと なぜ必要か
1 ClaudeSDKClient の最小構成 `async with`、`client.query()`、`client.receive_response()` の基本形を作る。
2 同じclientでフォローアップする 2回目の質問が1回目の文脈を持つことを確認する。
3 session_id を保存する あとで特定の会話に戻るための識別子を保存する。
4 resume で再開する プロセスを終了しても、保存済みセッションへ戻れるようにする。
5 複数ユーザー相当の会話を分ける `user_id` と `session_id` の対応を保存し、会話を混ぜない。
6 ストリーミング表示の基礎 `AssistantMessage` の途中応答を逐次表示し、CLIでチャット感を出す。
7 中断とエラー時の扱い `interrupt()`、`subtype`、`is_error`、保存タイミングを理解する。
8 ミニチャットCLIを作る 入力、履歴、セッション、終了コマンドを組み合わせる。

SDK concepts

この章で初めて出てくる関数・クラス・メソッド

まずは分類だけを押さえます。 詳細な引数や戻り値は、実際に使うレッスンで表に分けて説明します。

名前 分類 インスタンス生成 この章での見方
ClaudeSDKClient SDKのクラス 必要。ClaudeSDKClient(options=...) のように作る 同じ会話セッションを保ったまま、複数回の問い合わせを送るためのclient。
async with ClaudeSDKClient(...) 非同期コンテキストマネージャー clientを作って接続・終了を管理する 接続開始と終了を明示し、会話のライフサイクルを読みやすくする。
client.query() メソッド clientインスタンスから呼び出す 現在のclientに対してプロンプトを送る。応答本体はこの戻り値ではなく、次の `receive_response()` で読む。
client.receive_response() メソッド clientインスタンスから呼び出す 現在の問い合わせに対する `AssistantMessage` や `ResultMessage` を順に受け取る。
resume ClaudeAgentOptions の設定 不要。セッションIDを渡す 最新ではなく、特定の過去セッションへ戻るときに使う。
continue_conversation ClaudeAgentOptions の設定 不要。真偽値を渡す 現在のディレクトリで最新のセッションを続けるときに使う。

Session model

セッションの考え方

公式ドキュメントでは、セッションはAgentが動作する間にSDKが蓄積する会話履歴として説明されています。 プロンプト、ツール呼び出し、ツール結果、レスポンスが含まれ、SDKはそれをディスクに保存します。

セッションは会話を保持し、ファイルシステムは保持しません

セッションに戻ると、Agentは以前の会話文脈を持ちます。 ただし、ファイル変更をスナップショットして戻す機能とは別です。 ここを混同すると、resumeすれば作業ディレクトリも戻る、という誤解につながります。

名前 誰が持つか 用途
Claude SDKのセッション Agent SDK Claudeが過去のやり取りを踏まえて続きの応答をするため。
session_id SDKから返る ResultMessage 特定の会話を後から `resume` するため。
アプリ側の会話履歴 自分のPythonコードやDB 画面表示、一覧、検索、ユーザーごとの管理、監査のため。
user_id アプリ側 複数ユーザー相当の会話を混ぜないため。
