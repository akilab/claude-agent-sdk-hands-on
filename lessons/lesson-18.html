Lesson 18 / ClaudeSDKClient

SQLiteでテーブルを作成する

Lesson 17で設計した `users`、`sessions`、`messages` を、実際のSQLiteデータベースとして作成します。 Agent実行コードはまだ書かず、DBを作る準備コードだけに集中します。

所要時間 50分
ゴール Agentと分ける理由 保存場所 テーブル定義 処理の流れ 完成コードを読む 実行して確認 確認問題

Goal

このレッスンのゴール

このレッスンを一言で Agentを動かさず、後続レッスンで使う `data/agent_sessions.sqlite3` に3つのテーブルを作ります。

  • 共有関数 `connect_database()` でDBファイルへ接続できる
  • 共有関数 `create_schema()` で3テーブルを作成できる
  • `users`、`sessions`、`messages` の3テーブルを作成できる
  • 作成済みテーブルを `print_database_summary()` で確認できる

Separation

Agentコードとは分けて作る

この回ではClaude Agent SDKを実行しません。 DB作成とAgent実行を同じコードに入れると、学習者は「DB接続」「テーブル定義」「Agentへの問い合わせ」「レスポンス処理」を同時に読むことになります。 それでは主役がぼやけるため、まずDBの箱だけを独立して作ります。

今回作るもの

作るのはSQLiteファイルと3つのテーブルだけです。 ユーザーやメッセージの保存、`session_id` の登録、`resume` との接続は次のレッスン以降に回します。

DB処理はshared.databaseに切り出しています

この章の主役はClaude Agent SDKのセッション管理です。 SQLやsqlite3の細部を毎回読むと理解の妨げになるため、DB接続、テーブル作成、登録、確認の細かい処理は `python-labs/scripts/shared/database.py` にまとめています。

Database path

DBはdataフォルダに置く

今回作るDBはLesson 18だけの出力ではありません。 Lesson 19以降で、セッション台帳や会話本文を保存するために継続して使います。 そのため、実行結果置き場の `outputs/` ではなく、共有データ置き場の `python-labs/data/agent_sessions.sqlite3` に作成します。

場所 役割 今回の扱い
python-labs/data/ 後続レッスンでも使う共有データ agent_sessions.sqlite3 を作る
python-labs/outputs/ 各レッスンの実行結果やログ 今回はDB本体を置かない

Schema

3つのテーブルを作る

SQLiteでは、テーブルの形をSQL文で定義します。 ただし、この章で学びたいのはDBそのものではなく、Claudeのセッション情報をどこへ保存するかです。 そのためSQLの細部は `shared.database` に移し、このレッスンでは `create_schema()` を呼ぶだけにします。

テーブル 主な列 ポイント
users user_id, status status で現在状態を持つ
sessions user_id, claude_session_id, title, cwd Claude側のIDは claude_session_id として保存する
messages claude_session_id, role, content, turn_number 会話本文や結果ログのように増え続ける情報を置く
NULLを避ける設計に寄せます

`last_resumed_at` は、まだresumeしていない状態を空文字で表します。 実務ではNULLを使う設計も一般的ですが、この教材では「値がない状態」を読みやすくするため、まずNOT NULL中心で進めます。

すでにDBを作っていた場合

`create_schema()` の中では `CREATE TABLE IF NOT EXISTS` を使っています。 これは既存テーブルの列を作り直しません。 以前の版で `users.created_at` や `users.updated_at` を含むDBを作っていた場合は、DB Browserを閉じてから `data/agent_sessions.sqlite3` を削除し、このレッスンをもう一度実行してください。

Sequence

処理の流れを見る

`main()` がDBへ接続し、`create_schema()` で3つのテーブルを用意し、最後に作成済みテーブルを確認します。 DBの細かいSQLは `shared.database` に置いて、レッスン本体では流れだけを読みます。

Hands-on

完成コードを読む

`python-labs/scripts/lesson_18_create_sqlite_tables.py` の完成コードを確認します。 DBの細かい処理は `shared.database` に切り出してあります。 ここでは、後続レッスンで使うDBを準備する最小コードを確認します。

python-labs/scripts/lesson_18_create_sqlite_tables.py 
from shared.database import (
    connect_database,
    create_schema,
    print_database_summary,
)


# このファイルを直接実行したときの入口になる関数です。
def main() -> None:
    with connect_database() as connection:
        create_schema(connection)
        print_database_summary(connection)


if __name__ == "__main__":
    main()

Run

実行して確認

`python-labs/` から実行します。

Windows / macOS / Linux 
uv run python scripts/lesson_18_create_sqlite_tables.py

正常に動くと、`Database`、`Tables`、`Columns` が表示されます。 `Tables` に `messages`、`sessions`、`users` が出ていれば成功です。

完成版だけを確認したい場合は、次を実行します。

Windows / macOS / Linux 
uv run python scripts/lesson_18_create_sqlite_tables.py

DBファイルが作られたことを確認します。

Windows 
Test-Path data/agent_sessions.sqlite3
macOS / Linux 
test -f data/agent_sessions.sqlite3 && echo exists

Review

確認問題

  1. 今回のDBファイルを `outputs/` ではなく `data/` に置く理由は何ですか。
  2. なぜAgent実行コードとDB作成コードを分けるのですか。
  3. `create_schema()` は何を作る共有関数ですか。
  4. `sessions.id` と `sessions.claude_session_id` はどう違いますか。
  5. `messages` テーブルに本文を置く理由を説明してください。
